The L1 + L2 design note is below. I wrote no files.

Two findings change the earlier analysis:

- **QSA drains the GPU queue at every layer.** `advance()` refuses to finish a layer until the host has seen the last attention consumer complete (`S5/qsa_operation.py:2110`). The host therefore waits on the GPU at all 12 QSA layers per chunk. The bucket ordering on the GPU is already done with stream events (`:1879–1888`), so only the host side has to change.
- **The PP send runs on the compute stream.** The PP channel uses `split.prefill_stream` (`S5/native_startup.py:290–292`). Under L2, PP0's send for the next chunk waits for PP1 to post its receive. That only syncs the pipeline and does not deadlock.

The smallest step that proves the direction is Step A below: one command per dense QSA layer.

# Design note: L1 (fewer commands) + L2 (two chunks in flight across PP stages)

**Basis.**
- **Source:** `wt-claude-native43-held` (`S5/` = `patches/s5_engine/`). Line numbers will shift once held-g lands.
- **Baseline:** held-g = R1/R5 receipts + L3 (no empty-step pacing) + L4 (lean replies). held-f = rank-2 HOL direct replies + in-wait progress.
- **Labels:** [M] measured, [D] derived, [I] inferred.

Order: A, B, C0, C1. A is small to medium, B is small once A exists, C is large. C's gain does not depend on how host-bound the chunk is once GPU-bound, so if A fails its kill criterion, skip B and go to C.

## 2. Protocol changes per step

### Step A: one command per dense QSA layer

**Wire.**
- The PREPARE reply carries `dense_profiles`, one `(layer, QsaScheduleShape('dense_dma', (1,)*nb, (1,)*nb))` per QSA layer on the stage.
  - `nb = ceil(pages / ARENA_PAGES)`, where `ARENA_PAGES = 24` and `PAGE_TOKENS = 4048` (`S5/e3_types.py:30,32`).
  - The worker computes these from the same `metadata_plan_provider` (`S5/qsa_operation.py:351`) that the layers later bind at `bind_plan` (`:940`).
  - `_do_prepare` (`S5/lane_dispatch.py:334–360`) adds the field.
- A LAYER command for a QSA layer carries `mode='fused'` plus its grant in the existing `profile` field.

**Engine.**
- In `_apply_segments` for PREPARE, require identical `dense_profiles` from both stage peers, equal to the engine's own expectation from the admission block tables. Store them in `_profile_grants[(stage, layer)]`.
  - `_send_plan_entry` already attaches grants to LAYER commands (`S5/engine_driver.py:2177`).
- Fused layers never enter `phase='profile'` (`:1472`), never set `_tail_boundary` (`:1475–1488`), and never create a `TPTailSubmissionObligation` (`:739–759`).

**Why agreeing at PREPARE is safe.** PREPARE enqueues no collective, so the TP peers agree before the chunk's first collective, as today. A later grant mismatch on one peer means its local state changed after PREPARE. That is a contract violation and is handled by the watchdog (§3g), not a recoverable refusal.

**Worker (`qsa_driver`).** Add a fused path:
1. Run `_pre` (`S5/qsa_driver.py:286–336`).
2. Loop `operation.advance(fused=True)`. At the schedule boundary call `authorize_schedule(grant)` (`S5/qsa_operation.py:1506–1522`); it compares equal by construction.
3. On StopIteration, run `_tail` (`S5/qsa_driver.py:403–412`) in the same call and return the layer result. The cursor advances and the layer never pauses.

**`qsa_operation` in fused mode.**
- `advance()` skips the host `pending_buckets` refusal (`:2110`).
- `fill_bucket` skips the `MAX_OUTSTANDING_BUCKETS` check (`:1839`; the sparse path at `:1659` stays refused).
- Correctness is already GPU-ordered:
  - The copy stream waits on the producer and on `_last_arena_consumer` for bucket 0, and on `consumed[-1].event` for later buckets (`:1879–1888`).
  - Compute waits on the copy event.
  - `o_proj` runs on the same compute stream after attention.
  - `end_layer` checks only submission bookkeeping, not completion (`:1960–1993`).
- Ticket budget: ≤ 6 buckets per layer (`MAX_LAYER_PAGES = 128`), so ≤ ~13 tickets per layer and ≤ 78 per stage, within `MAX_TRACKED_TICKETS = 512` (`:85–88`).

**Refuse fused mode at PREPARE** unless all of these hold:
- the QSA policy is dense;
- no sparse source hold (`has_sparse_source`);
- no row1 qualifier attached, because `_qualify_pending_bucket` needs the host waits.

**Dispatcher.** For a fused command, `_do_layer` (`S5/lane_dispatch.py:391–416`) skips the credit query. It returns `paused/profile_boundary/tail_boundary = False`.

**Reply** (SegmentAcceptance):
- accepted;
- cursor `(layer+1, 'running', None)`;
- `collectives`: the count enqueued during this command;
- `host_submit_ns`;
- the held-g incremental report.

**NCCL sequence identity.** Both peers execute the same command with the same pre-granted bucket count, and buckets contain no collectives. The collective sequence per QSA layer is therefore the same on both peers [I, census below]:
- `canonical_selection` broadcast (`S5/lane_comm.py:161–184`);
- `o_proj` all-reduce;
- the MoE all-reduce in `_flash_e3_layer_post`.

**Collective ledger.** Proven per command:
- `PrefillTpCommunicator.collectives` already counts all-reduces (`S5/lane_comm.py:101,108`). Extend it to count the selection broadcast, which today calls `pynccl.broadcast` directly.
- The engine requires equal deltas across stage peers. This is added to the existing paused/cursor/boundary agreement (`S5/engine_driver.py:1412–1421`).

**Run-ahead bound without worker-side pending.** The engine sends layer/group k only when both peers' latest reports show k−2 complete; otherwise it sends a poll.
- Workers never return pending for a collective-bearing command, so one peer can never accept while the other pends. That case is today's tail hazard.

### Step B: groups

**Wire and engine.**
- Lift `layer segment must cover exactly one layer for now` (`S5/lane_dispatch.py:104`).
- The engine emits `layer_end = group_end` (`S5/engine_driver.py:2160`) with the plan split into 3 GDN + 1 QSA groups (QSA at 3, 7, …, 47).
- The `profile` field becomes the tuple of grants for the QSA layers in the range.

**Worker.**
- `_do_layer` loops `lane.layer(i)` over the range. Scopes stay per layer (`S5/model_hooks.py:626–649`) because the private scope and PLE scratch are per `layer_idx`.
- One op_seq per command. Record start/end events per layer (feeds R1). Completion uses the last layer's event, while drain uses all of them.

**Reply.** As in A, with cursor = `group_end` and collectives = the sum over the group.

**TP agreement.** Same check, with ledger equality per group. The run-ahead bound stays at ≤ 2 outstanding groups per stage, enforced engine-side.

**Group size.** Chosen from R3: worker launch ns per group ≤ ~10 ms. Under live decode, a stock RPC on that rank waits behind the group launch. Today's eager launch is ~3–4 ms per layer [I, from stock's launch-bound 512-token step, `README.md:117–119`].

### Steps C0/C1: two chunks in flight

**Engine.**
- Replace the single `tx/_command/_inflight` with a cursor per stage: `stage_tx[s]`, a per-stage plan slice, and one command in flight per stage.
- `advance()` services both cursors.
- Commands still travel on the broadcast MQ. Non-target ranks give held-g's token-sized skipped reply.
- Replies are demultiplexed by `(transaction, stage, op_seq)`.
- `_begin` gating (`:1878–1881`, `:2042–2091`) becomes per stage. Stage 0 may begin n+1 once n's `STATE_FINALIZE s0` and `PP_SEND` are accepted and PP0 has released n locally.
- The global release and commit of n still wait for all four ranks (`:2124–2139`).
- `PPTransferLedger` is already keyed by `(transaction, seq)` (`:607–717`).
- `state_epoch`: n+1 takes n's epoch + 1 at admission. The retained-row check (`:2050–2053`) then holds per stage.

**Worker.**
- Stage-local `release()` no longer needs `pp_consumer_proof` for the sender (`S5/lane_dispatch.py:569`).
  - The send ticket stays with `PrefillPPChannel`, and `release_send(ticket, proof)` (`S5/lane_comm.py:346`) runs when the proof arrives, after the transaction reset.
  - `PP_SLOTS = 2` (`:33`) limits PP0 to one chunk ahead.
  - A full slot must become a typed pre-enqueue E3Pending instead of `LaneCommError` (`:331–332`).
- `worker_bridge.open` (`S5/worker_bridge.py:355`) and the single metadata generation (`S5/lane_chunk.py:743–744`) stay unchanged. Each worker still runs one chunk at a time.

**Scheduler.**
- `_admit_observed` (`S5/scheduler_hooks.py:1673–1676`) may admit a successor of the same request while it is parked, once the driver signals that n finished stage 0. `max_active` (`:1329`) becomes 2 for the same-request successor only.
- Allocation uses the stock `allocate_slots(delay_cache_blocks=True)` (`:1798–1810`) with `num_computed_tokens` provisionally set to n's `chunk_end`. Precedent: `_ProjectedPrefillRequest` (`:1210–1222`).
- `commit(n)` (`:2006–2072`) does not re-prepend the request (`:2071`) when a successor is parked. `commit(n+1)` requires `commit(n)`.

**PP ordering.** Sends and receives on each PP channel stay in chunk order. PP0's send of n+1 sits on `prefill_stream` until PP1's stream reaches receive n+1. That is the natural pipeline sync; no cycle exists because PP1 never waits on PP0 except through that receive.

## 3. Invariants and how each is proven

**(a) Cancel/drain mid-group, exact checkpoint.**
- Stops land only between commands. A group is a concatenation of today's layer commands with the same buffer targets, so a stop after group k is the same state as today's stop after layer `4k+3`.
- `cancel` keeps all owners and drain waits for every recorded event (`S5/lane_dispatch.py:514–574`). Nothing uncommitted is published:
  - `delay_cache_blocks`;
  - `frontier.cancel`;
  - the align/CoW destination blocks.
- The checkpoint is the last committed `chunk_end`.
- In C, a cancel retires n+1 first, then n.
- Proof: a CPU cancel sweep at every command and reply index with one and two chunks in flight (P2), the VM spin-kernel cancel (V4), and a box stop-injection arm (§5).

**(b) Typed close/release.**
- `ReleaseAck` stays bound to the final completion report (`S5/scheduler_hooks.py:1990–2004`); C adds per-stage acks, and commit still needs all four.
- `close_request` needs no open transaction on that worker (`S5/lane_dispatch.py:600–604`).
- Proof: P2/P4 assert every ack matches the final report's `completed_sequence`.

**(c) Prefix-cache commit only at global release.**
- `cache_blocks(request, chunk_end)` runs only in `commit` (`:2035`), after `ready_to_commit` (`:1985–1988`).
- C adds two rules: commits happen in order, and n+1 is never cache-visible before its own commit.
- Proof: P4 asserts the sequence of `cache_blocks` calls and frontier publications.

**(d) Lifetime/leak oracles.** These must be empty at idle:
- `LifetimeLedger` (`S5/async_handoff.py:1338`);
- operation records and owners, cleared only at `release` (`S5/qsa_operation.py:2230–2285`);
- PP `outstanding()`;
- leases.

Proof: P2 asserts all of them are empty after every scenario; V4 checks the allocator returns to baseline over 200 cycles; the box runs the lifecycle/leak block on the final candidate.

**(e) CoW guard.**
- `check_update` (`S5/lane_hooks.py:650–665`) keeps refusing worker mutations without a scheduler lease proof.
- In C, `mutation_guard` must cover the leases of both parked chunks.
- Proof: P4 with decoders allocating while n and n+1 are parked (disjoint passes, overlapping refuses), extending the VM-proven guard case.

**(f) Metadata-generation lifetime.**
- One generation per worker; `admit` refuses while one is live (`S5/lane_chunk.py:743–744`); release only after drain (`S5/lane_dispatch.py:592–595`). Unchanged in A, B and C.
- Proof: P2/P4, plus VM V4 with a delayed consumer.

**(g) Stalled-peer watchdog** (a tail barrier inside NCCL can hang).
- **Detection:**
  - Immediately, when one stage peer accepts a collective-bearing command and the other refuses or quarantines. Today this raises at `:1363`; it is now classified `tp-divergent-collective`.
  - Timed, when an accepted collective-bearing op completes on no peer within `T_stall = max(2 s, 20 × R1 group p99)`, giving `tp-collective-stall`. This is far below `reply_timeout_s = 300 s` (`S5/engine_driver.py:775`).
  - Ledger mismatch, giving `tp-ledger-mismatch`.
- **Before declaring:** the stop path retries a command one peer accepted to the other peer with the same op_seq. This generalises `_drive_tail_stop_submission` (`:2385–2406`) to every fused or group command and to PREFIX s0.
- **Action is fail-closed:**
  - no further native commands;
  - no device synchronize or `empty_cache` on the lane (a later `cudaFree` would block the whole rank, decode included);
  - typed terminal route, then stop the engine through the existing fail-closed path; production comes back by the operator's rule.
- An `ncclCommAbort` recovery is out of scope until it is proven on the VM.
- Proof: P3 (fault after k enqueues, assert no synchronize), VM V5 (simulated hung collective).

|---|---|---|---|

### Layer 1: CPU connected probes

**Real objects used:**

- `PrefillAdmissionController` with vLLM's KVCacheManager/BlockPool (CPU Python), where the existing harness already composes it.

**Fixture leaves:**

|---|---|---|

| F2 simulator events | `torch.cuda.Event` in `_record` (`S5/lane_dispatch.py:226–234`; `S5/model_hooks.py:603–611`) | Only `record` and `query` are used |
| F3 `FakeCollective` (rendezvous by per-communicator index; never-matched stays pending) | PyNccl on the lane TP comm and PP channel | NCCL matches collectives by order per communicator, and that matching is the property under test. Blocking send/recv is modelled for the C deadlock check. |
| F4 `FakeLayer` (deterministic tensors; collective calls per layer as in the static census) | Generated `_flash_e3_forward_layer`, QSA pre/post, indexer | The protocol depends only on layer type, phases and collective calls; numerics are proven on the VM and box. |
| F5 in-process per-worker FIFO | executor broadcast MQ (`S5/executor_hooks.py:631–690`) | Same per-worker FIFO and reply set |
| F6 (only if F-real is unavailable) `FakeKVManager` | KVCacheManager | Declared signature: `allocate_slots`, `cache_blocks`, `get_computed_blocks` |

**Scenarios** (few, connected):
- **P1 trace equivalence.** Six solo chunks across 97,152 rows. The A/B/C device-op trace (ops per stream, order, collectives per communicator) must equal today's per-layer protocol.
- **P2 cancel sweep.** Stop at every command and reply index, for one and two chunks in flight. Check checkpoint exactness, empty ledgers and acks bound to final reports.
- **P3 peer divergence.** Fault after k enqueues on one peer. The watchdog classifies within T and no synchronize is called.
- **P4 C overlap with fake decoders mutating blocks.** Covers the CoW guard, commit order, `cache_blocks` only at global release, and PP send/recv with blocking semantics (no deadlock).
- **P5 control-path budget.** Per-op prepare/poll/validate/serialize counters; commands per chunk ≤ 66 (A), ≤ 30 (B, g = 4).

Each probe needs the hub-side container-shaped self-run, with failures classified HARNESS vs ENGINE.

### Layer 2: VM <vm-id> single 3090 (≤ 3 GiB, no TP/PP, 4-layer slice)

**V1 stream-event ordering of the fused QSA layer.**
- Setup: the real operation, arena (~96 MiB) and pinned host history above 24 pages, so ≥ 2 buckets.
- Spin-delay kernels are injected before copies and attention, 50 randomised runs.
- Pass: output bitwise equal to the host-credit path and to the row1 reference. This covers arena reuse across buckets and layers.

**V2 one group on the 3 GDN + 1 QSA slice of the reduced model** (TP1, as in earlier VM jobs).
- Pass: bitwise equal to four single-layer commands.
- Also measures R3: launch ns per layer and per group, which sets the group size.
- Caveat: TP1 short-circuits collectives, so the VM cannot count them.

**V3 R1 receipts.** Event-pair busy and idle times are compared against a CUPTI/nsys timeline of the slice; target agreement within ±5%.

**V4 cancel mid-group.**
- A spin kernel holds the group in flight.
- Pass: drain is false until the spin is released; afterwards release succeeds and allocator memory returns to baseline, over 200 cycles.

**V5 watchdog.**
- A spin kernel waits on a host-mapped flag on the lane stream, standing in for a hung NCCL kernel. A second stream (decode proxy) keeps progressing.
- Pass: the watchdog fires within T with `synchronize`/`empty_cache` instrumented to raise.

**The VM cannot prove:**
- TP and ledger agreement;
- PP ping-pong and blocking;
- x8 effects;
- 44/38 contention;
- W2 headroom.

Those stay with the box.

### Layer 3: box queue (one candidate per step, frozen bundle, one switch per arm)

**Arms:** `base` (step flag off) vs `cand` (on), ABBA over two rounds. Each arm runs:
- a solo fresh 197k dense prompt (no cohort, full prompt);
- a live W2 run with 8 decoders. Report the all-open window separately, since only ~15% of held-e's span had all 8 open.

The final step of each phase adds:
- the lifecycle/leak block (native28-style, 7,200 s);
- a stop-injection arm at a declared chunk and group index;
- a base-vs-base numerics control (gate v4).

**PASS:**
1. Correctness: startup-grade PASS, and none of the following: TP disagreements, ledger mismatches, watchdog fires, quarantines or crashes.
2. Numerics: sampled layer outputs bitwise equal to base. A, B and C are arithmetic-identical by design; otherwise INCONCLUSIVE until the control gives the envelope.
3. Performance, both rounds:
   - solo median period improves by ≥ 20% (A vs held-g), ≥ 10% (B vs A) or ≥ 30% (C1 vs B);
   - R1 confirms the mechanism: per-stage idle drops for A/B, and PP0/PP1 busy windows overlap ≥ 50% of the period for C1;
   - live decode ratio ≥ max(0.88, base − 0.02).
4. Memory: 0 OOM, minimum free at open ≥ base − 2 MiB, alloc_retries ≤ 1.1 × base.
5. Cancel arm: exact checkpoint, closure complete, `pp_receipts_pending` false.
6. Lifecycle/leak PASS on the final step.

**INCONCLUSIVE:** the two rounds disagree in direction, or a declared diagnostic fails.

**FAIL:** any violation of 1, 4 or 5.

## 6. Risk register and kill criteria

| # | Risk | Mitigation | Kill criterion |
|---|---|---|---|
| R1 | NCCL hang from a peer diverging inside a fused or group command | Agreement at PREPARE before the first collective; engine-side credit (no worker pending); retry before cancel; ledger; watchdog | Any ledger mismatch or watchdog fire on the box not explained by an injected fault: revert to the per-layer protocol and stop L1 |
| R2 | Cancel latency grows with GPU queue depth | Run-ahead ≤ 2 groups | Cancel-to-drain p99 > 500 ms |
| R3 | Worker launch blocks stock RPCs, so decode drops (B) | Group size from R3; g = 2 fallback | Live decode < base − 0.03 with group launch > 10 ms at g = 2: stay at A |
| R4 | Fused path not bitwise identical (workspace reuse, ordering) | V1/V2 bitwise checks; gate v4 control | Outside the envelope: FAIL |
| R5 | Memory tips W2 over | §4 checks; working-set admission before C1 | OOM or minimum free < base − 2 MiB |
| R6 | C scheduler: projected allocation, Mamba align/CoW with two parked chunks | P4 with the real KV manager | Not provable on CPU: don't build C1. Consider instead k pipelined 1,024-row micro-chunks inside one admission: about 2k/(k+1) of the full gain, scheduler unchanged, but coarser checkpoints and an intermediate GDN state to handle. |
| R7 | C: PP send blocks `prefill_stream` longer than expected | R1/R4 receipts; optional separate PP stream later | C1 gain < 1.25× with overlap < 30%: diagnose before further work |
| R8 | held-f assumes one command in flight | Move held-f's in-wait slot to per stage in C0 | — |
| R9 | Dense not yet accepted as default (n43 needs a current-vs-current control) | Run that control first | No dense default: L1 has no route past 97,152 rows, so it stays diagnostic |
| R10 | Thesis wrong (already GPU-bound after held-g) | R1 from held-g first | A gains < 10% and R1 per-stage idle falls < 30%: skip B, go to C |
